Below is a buildable, local-first, agent-driven motion-graphics production system designed around your constraints.

Important accuracy note:

• I cannot verify a current public “HyperFrames” API from here. To avoid inventing syntax, this design defines an internal, deterministic HyperFrames runtime contract under hyperframes/core/. If you later connect a different external HyperFrames renderer, only the adapter in hyperframes/core/runtime.ts and scripts/render-hyperframes.ts should need replacement.
• The Remotion code uses commonly documented Remotion v4 patterns: Composition, AbsoluteFill, useCurrentFrame, useVideoConfig, interpolate, spring, Sequence.
• OpenCode behavior is encoded operationally in AGENTS.md. If your OpenCode version has its own model configuration UI/config file, point its default coding model to LongCat 2.0 there. The repository contract is file-based, not magic-string-based.

The repository is a deterministic motion-design operating environment. The agent operates it; it does not freely improvise.

Runtime division

HyperFrames runtime

Used for:

• GSAP-driven choreography
• DOM/SVG-heavy scenes
• kinetic typography
• art-directed 2D motion
• camera-like transform choreography
• highly custom entrance behavior
• scenes where timeline control matters more than React composition

In this repository, HyperFrames means:

• a scene module
• a deterministic GSAP timeline
• a frame-seekable DOM renderer
• a headless browser capture pipeline
• FFmpeg encoding

The HyperFrames scene must be seekable by exact frame.

Remotion runtime

Used for:

• React component reuse
• data-driven scenes
• repeated list/table/card layouts
• parametric templates
• compositions where props determine content
• deterministic React rendering
• scenes that benefit from Remotion’s composition model

Remotion scenes must be pure functions of frame and props.

GSAP

GSAP is used inside HyperFrames for:

• timeline choreography
• stagger
• overshoot
• elastic settle
• camera-like transforms
• layered secondary motion

GSAP is not used as a substitute for a spec. Every GSAP timeline must map to frames and easing categories defined in the shot spec.

FFmpeg

Used for:

• encoding HyperFrames PNG sequences
• inspection frame extraction
• contact sheets
• final container conversion where needed

DaVinci Resolve Free

Used for:

• final editorial assembly
• color polish
• audio sync
• sound design
• final delivery
• human taste pass

Resolve is not used for core motion implementation.

# AGENTS.md

You are operating a deterministic motion-graphics production repository.

You are not here to “be creative” by rewriting the system.
You are here to implement, modify, and validate motion work inside a controlled factory.

The human supplies taste, references, direction, and final judgment.
The motion library supplies reusable animation behavior.
The runtime supplies execution.
You supply precise implementation and disciplined iteration.

## 1. Repository purpose

This repository produces high-quality 2D motion graphics using:

- HyperFrames for high-control DOM/GSAP scenes
- Remotion for React/data-driven scenes
- GSAP for timeline choreography inside HyperFrames
- TypeScript for implementation
- FFmpeg for encoding and inspection
- DaVinci Resolve for final assembly and finishing

This repository does NOT target After Effects.

## 2. Prime directives

Observe these rules in this order:

1. Preserve visual quality.
2. Preserve reliability.
3. Preserve maintainability.
4. Preserve automation.
5. Preserve convenience.

If a request conflicts with these priorities, choose the higher priority.

## 3. Mandatory startup behavior

Before modifying any file:

1. Read this file.
2. Read `skills/motion-language.md`.
3. Read `skills/shot-specification.md`.
4. Read `skills/hyperframes-vs-remotion.md`.
5. Read the active project’s `project.md`.
6. Read the active shot’s YAML spec if one exists.
7. Read existing scene code before changing it.
8. Check `motion/` for an existing primitive before writing new animation logic.

Do not propose code changes based only on the prompt.

## 4. Inspection protocol

When asked to modify a scene:

1. Identify the project and shot.
2. Open the shot spec:
   - `projects/<project>/specs/<shot>.yaml`
3. Open the implementation entry:
   - HyperFrames: `hyperframes/scenes/<sceneId>/entry.ts`
   - Remotion: composition registered in `remotion/Root.tsx`
4. Identify:
   - duration
   - fps
   - resolution
   - runtime
   - sequence steps
   - negative instructions
   - asset references
5. Only then modify code.

If no shot spec exists:

1. Create a minimal valid shot spec first.
2. Validate it.
3. Then implement.

Never implement a shot without a spec unless explicitly told to create a throwaway test.

## 5. Runtime selection

Use HyperFrames when:

- the shot depends on GSAP timeline choreography
- the shot uses DOM/SVG art direction
- the shot requires complex kinetic type
- the shot needs layered entrance/exit choreography
- the shot needs custom camera-like transform behavior
- React component reuse is not the primary value

Use Remotion when:

- the shot is data-driven
- the shot repeats structured components
- the shot is parametric
- the shot benefits from React composition
- the shot is a template
- content changes are driven by props

If both are plausible:

- choose HyperFrames for choreography-heavy shots
- choose Remotion for structure-heavy shots

Never choose a runtime based on novelty.

## 6. GSAP usage rules

Use GSAP only inside HyperFrames scenes or GSAP-specific motion primitives.

GSAP timelines must be:

- paused
- deterministic
- frame-seekable
- driven by the scene’s fps
- constructed from frame counts, not ad-hoc seconds
- free of `Date.now()`, `Math.random()`, or async timing

Do not use:

- `setTimeout`
- `setInterval`
- `requestAnimationFrame`
- event-driven animation state

for core shot motion.

All GSAP animation must be inspectable by seeking a frame.

## 7. Primitive reuse rules

Before writing any animation behavior, search `motion/` for an existing primitive.

Reuse a primitive when:

- it already expresses the required behavior
- it can be parameterized without breaking its API
- it is close enough that extension is safer than reimplementation

Do not create a new primitive if:

- the behavior is scene-specific
- the behavior is only used once
- the behavior is a composition of existing primitives
- the behavior can be expressed with existing GSAP easing and transforms

A new primitive is justified only when:

1. the behavior is reusable across scenes
2. the behavior has a stable API
3. the behavior is deterministic
4. the behavior cannot be cleanly expressed by existing primitives
5. the primitive can be documented and validated

When creating a new primitive:

- place it in the correct `motion/` subdirectory
- use a clear verb or noun-verb name
- accept a typed options object
- provide defaults
- avoid DOM coupling unless it is a DOM primitive
- do not introduce a new dependency without strong justification

## 8. Shot specification interpretation

A shot spec is the source of truth.

When implementing a spec:

- implement exactly the declared runtime
- preserve the declared fps
- preserve the declared resolution
- preserve the declared duration
- honor all `negative` instructions
- honor all asset constraints
- map sequence steps to timeline events
- use easing names from the controlled

Rules:
• one shot has one fps
• do not mix frame bases
• do not assume 60fps unless spec says so
• holds are valid timing choices
• pauses are valid timing choices
• stagger must be intentional, not decorative
• entrances must not all start on the same frame unless the spec requires it
13. Frame rate rules
Allowed default fps values:
• 24
• 25
• 30
• 50
• 60
If a spec uses another fps, validation must fail unless the project explicitly overrides allowed fps.
Do not:
• change fps to make timing easier
• retarget animation by changing fps
• mix fps between spec and implementation
14. Dimension rules
Resolution must come from the shot spec.
Do not:
• hardcode 1920x1080 in scene logic when a spec exists
• change aspect ratio casually
• use percentage-based layout that breaks intended composition at spec resolution
If a scene is responsive, it must still be art-directed at the spec resolution.

• change type hierarchy casually

All renders must be repeatable.
Forbidden in scene code:
• Math.random()
• crypto.getRandomValues()
• unseeded procedural generation
• Date.now()
• performance.now() for motion logic
• network-fetched content required for frame calculation
• async timers driving animation
Allowed:
• seeded RNG from motion/core/rng.ts
• pure functions of frame
• deterministic GSAP timelines
• local assets
If randomness is needed:
1. use seededRandom(seed)
2. derive all random values at construction time
3. keep them stable across frames

# Motion Language

This skill defines how motion design decisions are translated into operational rules.

The purpose is to prevent generic, weightless, evenly-eased animation.

## 1. Timing vocabulary

### Anticipation

A preparatory movement before the main action.

Use when:

- an object enters forcefully
- a title impacts
- a camera move begins
- an element prepares to exit

Operational rule:

- if an element moves fast, add a smaller preparatory movement before the main movement
- anticipation should usually be shorter than the main action

Example:

- title pulls back 2–4% of width before launching in
- shape compresses slightly before jumping

### Acceleration

The rate at which motion gains speed.

Rules:

- entrances often begin slow and accelerate
- mechanical motion may accelerate sharply
- cinematic motion usually accelerates gently

Avoid:

- instant full-speed motion unless the style is hard-cut

### Deceleration

The rate at which motion slows.

Rules:

- most elements should decelerate into rest
- deceleration should be longer than acceleration for elegant motion
- sharp graphics may use short deceleration

Avoid:

- stopping abruptly without settle unless the style is mechanical

### Overshoot

The element passes its target slightly and returns.

Use when:

- playful motion
- kinetic type
- snappy UI motion
- impact emphasis

Rules:

- overshoot amount should be small unless the style is broad
- overshoot must settle
- overshoot is not a substitute for anticipation

### Settle

The return from overshoot or residual motion to rest.

Rules:

- settle must be visible but controlled
- elastic settle should have hierarchy
- do not make every element settle identically

### Holds

A full stop.

Rules:

- holds are powerful
- a hold can create emphasis
- do not fear stillness

Avoid:

- constant micro-motion when the shot needs clarity

### Pauses

A timing gap between events.

Rules:

- pauses create rhythm
- use pauses before important reveals
- do not fill every frame with action

### Stagger

Offsetting the timing of related elements.

Rules:

- stagger should reveal hierarchy
- stagger should usually be small
- stagger direction should follow reading order or spatial logic

Avoid:

- identical stagger on unrelated elements
- random stagger without visual logic

### Overlap

Related elements do not start and stop at the same time.

Rules:

- primary action leads
- secondary action follows
- background/environment trails or drifts independently

### Follow-through

Secondary elements continue moving after the primary element stops.

Rules:

- use for tails, underlines, particles, supporting shapes
- keep it subtle

## 2. Spatial behavior

### Screen direction

Motion direction must have meaning.

Rules:

- preserve directional continuity across shots
- left-to-right often reads as progression
- right-to-left can read as return or opposition
- vertical motion should imply hierarchy or arrival

### Hierarchy

Only one dominant motion should own the viewer’s attention at a time.

Rules:

- primary element moves first or strongest
- secondary elements support
- tertiary elements decorate
- environment never competes with primary message

### Focal point

Every moment must have one clear focal point.

Rules:

- place focal point in a strong composition zone
- use contrast, motion, and scale to reinforce it
- do not animate corners unless they matter

### Relative movement

Elements should relate to each other spatially.

Rules:

- supporting elements should respond to primary elements
- background movement should be slower than foreground
- parallax should imply depth, not just drift

### Depth

Depth is created by:

- scale
- parallax
- blur
- value contrast
- speed difference

Rules:

- background moves slower
- foreground moves faster
- camera moves should affect layers differently

## 3. Motion hierarchy

### Primary elements

These carry the message.

Examples:

- main title
- hero product
- core graphic
- central callout

Behavior:

- strongest motion
- clearest timing
- best easing
- most deliberate entrance/exit

### Secondary elements

These support the primary message.

Examples:

- subtitle
- underline
- supporting shape

# HyperFrames vs Remotion Decision System

Use this skill whenever choosing a runtime.

## Choose HyperFrames if any of these are true

1. The shot depends on GSAP timeline choreography.
2. The shot is heavily art-directed in DOM/SVG.
3. The shot uses kinetic typography with custom entrances.
4. The shot needs layered secondary motion with precise overlaps.
5. The shot uses camera-like transform choreography.
6. The shot depends on custom DOM effects or filters.
7. The shot’s difficulty is choreography, not data.

## Choose Remotion if any of these are true

1. The shot is data-driven.
2. The shot repeats many structured items.
3. The shot is a template.
4. The shot is driven by props.
5. The shot benefits from React components.
6. The shot needs many variants from one structure.
7. The shot’s difficulty is structure, not choreography.

## Decision matrix

| Condition | Prefer |
|---|---|
| Complex GSAP choreography | HyperFrames |
| Kinetic type | HyperFrames |
| Custom DOM/SVG art direction | HyperFrames |
| Repeated React rows/cards | Remotion |
| Data-driven props | Remotion |
| Template variants | Remotion |
| Timeline-heavy motion | HyperFrames |
| Component-heavy structure | Remotion |
| Deterministic parametric layout | Remotion |
| Cinematic camera-like transforms | HyperFrames |

## Tie-breakers

If both are plausible:

1. If the shot needs expressive timeline control, choose HyperFrames.
2. If the shot needs parametric reuse, choose Remotion.
3. If the shot is one-off and art-directed, choose HyperFrames.
4. If the shot will be repeated with changing content, choose Remotion.

## Forbidden reasons

Do not choose a runtime because:

- it seems newer
- it is more fun
- it is easier to guess
- it avoids reading the spec

## Runtime boundaries

HyperFrames owns:

- GSAP choreography
- DOM/SVG scene construction
- frame seeking
- headless capture

Remotion owns:

- React composition
- frame interpolation
- props-driven rendering
- deterministic component trees

Do not mix them in one scene unless an explicit adapter is required.

export function clamp01(value: number): number {
  return value < 0 ? 0 : value > 1 ? 1 : value;
}

export function framesToSeconds(frames: number, fps: number): number {
  if (fps <= 0) throw new Error("fps must be greater than 0");
  return frames / fps;
}

export function secondsToFrames(seconds: number, fps: number): number {
  if (fps <= 0) throw new Error("fps must be greater than 0");
  return Math.round(seconds * fps);
}

export function normalizedProgress(
  frame: number,
  startFrame: number,
  durationFrames: number
): number {
  if (durationFrames <= 0) return 1;
  return clamp01((frame - startFrame) / durationFrames);
}

import { clamp01 } from "./frames";

export interface InterpolateOptions {
  clamp?: boolean;
}

export function interpolate(
  frame: number,
  input: [number, number],
  output: [number, number],
  options: InterpolateOptions = {}
): number {
  const [inStart, inEnd] = input;
  const [outStart, outEnd] = output;

  if (inEnd === inStart) return outStart;

  let t = (frame - inStart) / (inEnd - inStart);

  if (options.clamp !== false) {
    t = clamp01(t);
  }

  return outStart + t * (outEnd - outStart);
}

export function seededRandom(seed: number): () => number {
  let a = seed >>> 0;

  return function () {
    a |= 0;
    a = (a + 0x6d2b79f5) | 0;

    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;

    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

export function pickSeeded<T>(rng: () => number, items: T[]): T {
  if (items.length === 0) throw new Error("items must not be empty");
  return items[Math.floor(rng() * items.length)];
}


motion/core/spring.ts

export interface SpringConfig {
  stiffness?: number;
  damping?: number;
  mass?: number;
}

export interface SpringOptions {
  fps: number;
  startFrame: number;
  from: number;
  to: number;
  config?: SpringConfig;
}

export function springValue(frame: number, options: SpringOptions): number {
  const { fps, startFrame, from, to } = options;
  const stiffness = options.config?.stiffness ?? 120;
  const damping = options.config?.damping ?? 14;
  const mass = options.config?.mass ?? 1;

  if (frame <= startFrame) return from;

  const steps = Math.floor(frame - startFrame);
  const dt = 1 / fps;

  let x = from;
  let v = 0;

  for (let i = 0; i < steps; i++) {
    const springForce = -stiffness * (x - to);
    const damperForce = -damping * v;
    const acceleration = (springForce + damperForce) / mass;

    v += acceleration * dt;
    x += v * dt;
  }

  return x;
}

export const GSAP_EASE: Record<EasingName, string> = {
  linear: "none",
  smooth: "power2.inOut",
  sharp: "power4.out",
  elastic: "elastic.out(1,0.6)",
  overshoot: "back.out(2.2)",
  mechanical: "steps(12)",
  cinematic: "power3.inOut",
  organic: "sine.inOut"
};

export const EASING_FUNCTIONS: Record<EasingName, (t: number) => number> = {
  linear: (t) => t,
  smooth: (t) => t * t * (3 - 2 * t),
  sharp: (t) => 1 - Math.pow(1 - t, 4),
  elastic: (t) => {
    if (t === 0 || t === 1) return t;
    const p = 0.3;
    return Math.pow(2, -10 * t) * Math.sin(((t - p / 4) * (2 * Math.PI)) / p) + 1;
  },
  overshoot: (t) => {
    const s = 1.70158;
    const u = t - 1;
    return u * u * ((s + 1) * u + s) + 1;
  },
  mechanical: (t) => Math.floor(t * 12) / 12,
  cinematic: (t) =>
    t < 0.5 ? 4 * t * t * t : 1 - Math.pow(-2 * t + 2, 3) / 2,
  organic: (t) => 0.5 - 0.5 * Math.cos(Math.PI * t)
};

import { framesToSeconds } from "../core/frames";
import { GSAP_EASE } from "../easing";
import type { EasingName } from "../spec/shot-spec";

export interface CharRevealOptions {
  text: string;
  fps: number;
  startFrame: number;
  staggerFrames?: number;
  durationPerCharFrames?: number;
  ease?: EasingName;
  y?: number;
  opacity?: number;
}

export function splitTextIntoChars(
  root: HTMLElement,
  text: string
): HTMLSpanElement[] {
  root.textContent = "";

  const chars: HTMLSpanElement[] = [];

  for (const ch of text) {
    const span = document.createElement("span");
    span.textContent = ch;
    span.style.display = "inline-block";
    span.style.whiteSpace = "pre";
    root.appendChild(span);
    chars.push(span);
  }

  return chars;
}

export function charRevealTimeline(
  root: HTMLElement,
  options: CharRevealOptions
): gsap.core.Timeline {
  const chars = splitTextIntoChars(root, options.text);

  const tl = gsap.timeline({ paused: true });

  const duration = framesToSeconds(
    options.durationPerCharFrames ?? 8,
    options.fps
  );

  const stagger = framesToSeconds(options.staggerFrames ?? 2, options.fps);
  const ease = GSAP_EASE[options.ease ?? "smooth"];

  chars.forEach((span, i) => {
    tl.fromTo(
      span,
      {
        opacity: options.opacity ?? 0,
        y: options.y ?? 18
      },
      {
        opacity: 1,
        y: 0,
        duration,
        ease
      },
      framesToSeconds(options.startFrame, options.fps) + i * stagger
    );
  });

  return tl;
}

Why this belongs in Remotion

This scene belongs in Remotion because:

• it is data-driven
• it repeats structured rows
• it benefits from React mapping
• it is template-like
• its complexity is structural, not choreographic
• props can change content without changing scene code

If the same shot required aggressive kinetic type, impact compression, and layered GSAP choreography, it would belong in HyperFrames instead.

export interface CliOptions {
  [key: string]: string | boolean;
}

export function parseArgs(argv: string[]): CliOptions {
  const opts: CliOptions = {};

  for (let i = 0; i < argv.length; i++) {
    const arg = argv[i];

    if (!arg.startsWith("--")) continue;

    const key = arg.slice(2);
    const next = argv[i + 1];

    if (next === undefined || next.startsWith("--")) {
      opts[key] = true;
    } else {
      opts[key] = next;
      i++;
    }
  }

  return opts;
}

export function required(opts: CliOptions, key: string): string {
  const value = opts[key];

  if (typeof value !== "string" || value.length === 0) {
    throw new Error(`Missing required --$`{key}`);
  }

  return value;
}

import fs from "node:fs";
import path from "node:path";

export function ensureDir(dir: string): void {
  fs.mkdirSync(dir, { recursive: true });
}

export function walk(dir: string, extensions?: string[]): string[] {
  if (!fs.existsSync(dir)) return [];

  const results: string[] = [];

  const entries = fs.readdirSync(dir, { withFileTypes: true });

  for (const entry of entries) {
    const fullPath = path.join(dir, entry.name);

    if (entry.isDirectory()) {
      results.push(...walk(fullPath, extensions));
    } else {
      if (!extensions) {
        results.push(fullPath);
        continue;
      }

      if (extensions.some((ext) => fullPath.endsWith(ext))) {
        results.push(fullPath);
      }
    }
  }

  return results;
}

import { spawnSync } from "node:child_process";

export function run(command: string, args: string[]): void {
  const result = spawnSync(command, args, {
    stdio: "inherit",
    shell: process.platform === "win32"
  });

  if (result.status !== 0) {
    throw new Error(`Command failed: `${command} $`{args.join(" ")}`);
  }
}

export function output(command: string, args: string[]): string {
  const result = spawnSync(command, args, {
    encoding: "utf8",
    shell: process.platform === "win32"
  });

  if (result.status !== 0) {
    throw new Error(
      `Command failed: `${command} $`{args.join(" ")}\n`${result.stderr}`
    );
  }

  return result.stdout;
}

import fs from "node:fs";
import path from "node:path";
import { pathToFileURL } from "node:url";
import esbuild from "esbuild";
import { chromium } from "playwright";
import { ROOT, TMP, assetsDir, projectDir } from "./paths";
import { ensureDir } from "./files";
import { run } from "./exec";
import type { ShotSpec } from "../../motion/spec/shot-spec";

export interface RenderHyperframesOptions {
  project: string;
  shot: string;
  spec: ShotSpec;
  out: string;
  scale?: number;
  crf?: number;
  frameStep?: number;
  alpha?: boolean;
}

export async function renderHyperframes(
  options: RenderHyperframesOptions
): Promise<void> {
  const { project, shot, spec, out } = options;

  const sceneId = spec.implementation.sceneId;

  if (!sceneId) {
    throw new Error("HyperFrames spec requires implementation.sceneId");
  }

  const scale = options.scale ?? 1;
  const crf = options.crf ?? 18;
  const frameStep = options.frameStep ?? 1;

  const entry = path.join(ROOT, "hyperframes", "scenes", sceneId, "entry.ts");

  if (!fs.existsSync(entry)) {
    throw new Error(`Missing HyperFrames entry: `${entry}`);
  }

  const workDir = path.join(TMP, "hyperframes", `$`{project}-`${shot}`);
  const framesDir = path.join(workDir, "frames");

  ensureDir(workDir);
  ensureDir(framesDir);

  for (const file of fs.readdirSync(framesDir)) {
    fs.rmSync(path.join(framesDir, file));
  }

  const bundlePath = path.join(workDir, "bundle.js");

  await esbuild.build({
    entryPoints: [entry],
    bundle: true,
    outfile: bundlePath,
    format: "iife",
    platform: "browser",
    target: "es2022",
    define: {
      "process.env.NODE_ENV": '"production"'
    },
    logLevel: "silent"
  });

  const html = `<!doctype html>
<html>
<head>
<meta charset="utf-8" />
<style>
html, body { margin: 0; padding: 0; background: #000; }
</style>
</head>
<body>
<div id="hf-root"></div>
<script>
window.__HF_CONFIG__ = $`{JSON.stringify({
    seed: spec.seed ?? 12345,
    assetsBase: pathToFileURL(assetsDir(project) + path.sep).href
  })};
</script>
<script src="./bundle.js"></script>
</body>
</html>`;

  const htmlPath = path.join(workDir, "index.html");
  fs.writeFileSync(htmlPath, html, "utf8");

  const browser = await chromium.launch({
    args: ["--allow-file-access-from-files"]
  });

  const page = await browser.newPage();

  await page.setViewportSize({
    width: Math.round(spec.width * scale),
    height: Math.round(spec.height * scale)
  });

  await page.goto(pathToFileURL(htmlPath).href);

  await page.waitForFunction(() => (window as any).__HF_READY__ === true, undefined, {
    timeout: 60000
  });

  if (scale !== 1) {
    await page.evaluate(
      ({ scale }) => {
        const root = document.getElementById("hf-root");
        if (!root) return;
        root.style.transform = `scale(`${scale})`;
        root.style.transformOrigin = "top left";
      },
      { scale }
    );
  }

  let outputIndex = 0;

  for (let frame = 0; frame < spec.durationFrames; frame += frameStep) {
    await page.evaluate((f) => {
      (window as any).__HF_SEEK__?.(f);
    }, frame);

    const fileName = `$`{String(outputIndex).padStart(6, "0")}.png`;

    await page.screenshot({
      path: path.join(framesDir, fileName),
      type: "png"
    });

    outputIndex++;
  }

  await browser.close();

  const outputFps = spec.fps / frameStep;

  ensureDir(path.dirname(out));

  if (options.alpha) {
    run("ffmpeg", [
      "-y",
      "-framerate",
      String(outputFps),
      "-i",
      path.join(framesDir, "%06d.png"),
      "-c:v",
      "qtrle",
      "-pix_fmt",
      "argb",
      out.replace(/\.(mp4|mov)`$/i, ".mov")
    ]);
  } else {
    run("ffmpeg", [
      "-y",
      "-framerate",
      String(outputFps),
      "-i",
      path.join(framesDir, "%06d.png"),
      "-c:v",
      "libx264",
      "-preset",
      "veryfast",
      "-crf",
      String(crf),
      "-pix_fmt",
      "yuv420p",
      out
    ]);
  }
}

import path from "node:path";
import { parseArgs, required } from "./lib/args";
import { loadSpec } from "./lib/spec";
import { previewsDir } from "./lib/paths";
import { ensureDir } from "./lib/files";
import { renderHyperframes } from "./lib/hyperframes";
import { renderRemotion, writeRemotionProps } from "./lib/remotion";

async function main() {
  const opts = parseArgs(process.argv.slice(2));
  const project = required(opts, "project");
  const shot = required(opts, "shot");

  const spec = loadSpec(project, shot);
  const out = path.join(previewsDir(project), `$`{shot}_preview.mp4`);

  ensureDir(path.dirname(out));

  if (spec.runtime === "hyperframes") {
    await renderHyperframes({
      project,
      shot,
      spec,
      out,
      scale: 0.5,
      crf: 23,
      frameStep: 1
    });
  } else {
    const compositionId = spec.implementation.compositionId;

    if (!compositionId) {
      throw new Error("Remotion spec requires implementation.compositionId");
    }

    const propsFile = writeRemotionProps(project, shot, spec);

    renderRemotion({
      compositionId,
      out,
      propsFile,
      scale: 0.5
    });
  }

  console.log(`Preview written: `${out}`);
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});

ts
import fs from "node:fs";
import path from "node:path";
import { spawnSync } from "node:child_process";
import { parseArgs, required } from "./lib/args";
import { loadSpec } from "./lib/spec";
import { metadataDir, previewsDir } from "./lib/paths";
import { ensureDir } from "./lib/files";

function ffprobe(file: string): any {
  const result = spawnSync(
    "ffprobe",
    ["-v", "error", "-print_format", "json", "-show_format", "-show_streams", file],
    {
      encoding: "utf8",
      shell: process.platform === "win32"
    }
  );

  if (result.status !== 0) {
    throw new Error(`ffprobe failed for $`{file}`);
  }

  return JSON.parse(result.stdout);
}

function parseFps(rFrameRate: string): number {
  const [num, den] = rFrameRate.split("/").map(Number);
  if (!num || !den) return 0;
  return num / den;
}

async function main() {
  const opts = parseArgs(process.argv.slice(2));
  const project = required(opts, "project");
  const shot = required(opts, "shot");

  const spec = loadSpec(project, shot);

  const input =
    typeof opts.file === "string"
      ? opts.file
      : path.join(previewsDir(project), ``${shot}_preview.mp4`);

  if (!fs.existsSync(input)) {
    throw new Error(`Input not found: $`{input}`);
  }

  const probe = ffprobe(input);
  const videoStream = probe.streams.find((s: any) => s.codec_type === "video");

  if (!videoStream) {
    throw new Error("No video stream found");
  }

  const actual = {
    width: videoStream.width,
    height: videoStream.height,
    fps: parseFps(videoStream.r_frame_rate),
    duration: Number(probe.format.duration)
  };

  const reportDir = metadataDir(project);
  ensureDir(reportDir);

  const reportPath = path.join(reportDir, ``${shot}.inspection.json`);
  const markdownPath = path.join(reportDir, `$`{shot}.inspection.md`);
  const contactPath = path.join(reportDir, ``${shot}.contact.png`);

  fs.writeFileSync(
    reportPath,
    JSON.stringify(
      {
        input,
        spec: {
          width: spec.width,
          height: spec.height,
          fps: spec.fps,
          durationFrames: spec.durationFrames,
          expectedDurationSeconds: spec.durationFrames / spec.fps
        },
        actual,
        problems: {
          widthMismatch: actual.width !== spec.width,
          heightMismatch: actual.height !== spec.height,
          fpsMismatch: Math.abs(actual.fps - spec.fps) > 0.5,
          durationMismatch:
            Math.abs(
              actual.duration - spec.durationFrames / spec.fps
            ) > 0.25
        }
      },
      null,
      2
    ),
    "utf8"
  );

  const duration = Number(probe.format.duration) || 1;
  const rate = Math.max(0.05, 16 / duration);

  spawnSync(
    "ffmpeg",
    [
      "-y",
      "-i",
      input,
      "-vf",
      `fps=$`{rate},scale=480:-1,tile=4x4`,
      "-frames:v",
      "1",
      contactPath
    ],
    {
      stdio: "ignore",
      shell: process.platform === "win32"
    }
  );

  const markdown = `# Inspection Report: `${shot}

- input: \`$`{input}\`
- actual width: `${actual.width}
- actual height: $`{actual.height}
- actual fps: `${actual.fps.toFixed(2)}
- actual duration: $`{actual.duration.toFixed(2)}s

## Expected

- width: `${spec.width}
- height: $`{spec.height}
- fps: `${spec.fps}
- duration: $`{(spec.durationFrames / spec.fps).toFixed(2)}s

## Review checklist

- [ ] hierarchy is clear
- [ ] timing feels intentional
- [ ] easing is not uniform
- [ ] typography is readable
- [ ] camera movement is motivated
- [ ] effects are restrained
- [ ] no random flicker
- [ ] no unintended synchronization
`;

  fs.writeFileSync(markdownPath, markdown, "utf8");

  console.log(`Inspection JSON: `${reportPath}`);
  console.log(`Inspection Markdown: $`{markdownPath}`);
  console.log(`Contact sheet: `${contactPath}`);
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});

import fs from "node:fs";
import path from "node:path";
import { PROJECTS, TMP } from "./lib/paths";
import { ensureDir } from "./lib/files";

if (fs.existsSync(TMP)) {
  fs.rmSync(TMP, { recursive: true, force: true });
}

const projects = fs.readdirSync(PROJECTS, { withFileTypes: true });

for (const project of projects) {
  if (!project.isDirectory()) continue;

  const previews = path.join(PROJECTS, project.name, "previews");
  const renders = path.join(PROJECTS, project.name, "renders");

  if (fs.existsSync(previews)) {
    fs.rmSync(previews, { recursive: true, force: true });
    ensureDir(previews);
    fs.writeFileSync(path.join(previews, ".gitkeep"), "", "utf8");
  }

  if (fs.existsSync(renders)) {
    fs.rmSync(renders, { recursive: true, force: true });
    ensureDir(renders);
    fs.writeFileSync(path.join(renders, ".gitkeep"), "", "utf8");
  }
}

console.log("Cleaned temporary files, previews, and renders.");

import fs from "node:fs";
import path from "node:path";
import { PROJECTS, ROOT, HYPERFRAMES_SCENES } from "./lib/paths";
import { walk } from "./lib/files";
import { loadSpecFile } from "./lib/spec";
import { REMOTION_COMPOSITIONS } from "../../remotion/registry";
import type { ShotSpec } from "../../motion/spec/shot-spec";
import { parseArgs } from "./lib/args";

interface Problem {
  file: string;
  message: string;
}

const ALLOWED_FPS = [24, 25, 30, 50, 60];

function findSpecFiles(project?: string): string[] {
  if (project) {
    return walk(path.join(PROJECTS, project, "specs"), [".yaml", ".yml"]);
  }

  return walk(PROJECTS, [".yaml", ".yml"]).filter((file) =>
    file.includes(`$`{path.sep}specs`${path.sep}`)
  );
}

function validateSpec(
  spec: ShotSpec,
  file: string,
  problems: Problem[]
): void {
  if (!ALLOWED_FPS.includes(spec.fps)) {
    problems.push({
      file,
      message: `Invalid fps: $`{spec.fps}. Allowed: `${ALLOWED_FPS.join(", ")}`
    });
  }

  if (spec.width % 2 !== 0 || spec.height % 2 !== 0) {
    problems.push({
      file,
      message: "Width and height must be even for H.264 compatibility."
    });
  }

  if (spec.durationFrames <= 0) {
    problems.push({
      file,
      message: "durationFrames must be positive."
    });
  }

  const knownTargets = new Set<string>(["camera", "root"]);

  for (const element of spec.elements ?? []) {
    knownTargets.add(element.id);
  }

  for (const typo of spec.typography ?? []) {
    knownTargets.add(typo.id);
  }

  for (const step of spec.sequence) {
    if (!knownTargets.has(step.target)) {
      problems.push({
        file,
        message: `Sequence target not found: $`{step.target}`
      });
    }

    if (step.atFrame + step.durationFrames > spec.durationFrames) {
      problems.push({
        file,
        message: `Sequence step `${step.id} exceeds shot duration.`
      });
    }
  }

  for (const transition of spec.transitions ?? []) {
    if (!knownTargets.has(transition.target)) {
      problems.push({
        file,
        message: `Transition target not found: $`{transition.target}`
      });
    }
  }

  const projectDir = path.resolve(path.dirname(file), "..");

  for (const asset of spec.assets ?? []) {
    if (asset.required === false) continue;

    if (asset.path.startsWith("system:")) continue;

    const assetPath = path.join(projectDir, asset.path);

    if (!fs.existsSync(assetPath)) {
      problems.push({
        file,
        message: `Missing asset: `${asset.path}`
      });
    }
  }

  if (spec.runtime === "hyperframes") {
    const sceneId = spec.implementation.sceneId;

    if (!sceneId) {
      problems.push({
        file,
        message: "HyperFrames runtime requires implementation.sceneId"
      });
    } else {
      const entry = path.join(HYPERFRAMES_SCENES, sceneId, "entry.ts");

      if (!fs.existsSync(entry)) {
        problems.push({
          file,
          message: `Missing HyperFrames entry: $`{entry}`
        });
      }
    }
  }

  if (spec.runtime === "remotion") {
    const compositionId = spec.implementation.compositionId;

    if (!compositionId) {
      problems.push({
        file,
        message: "Remotion runtime requires implementation.compositionId"
      });
    } else {
      const exists = REMOTION_COMPOSITIONS.some(
        (comp) => comp.id === compositionId
      );

      if (!exists) {
        problems.push({
          file,
          message: `Remotion composition not registered: `${compositionId}`
        });
      }
    }
  }
}

function validateDuplicatePrimitives(problems: Problem[]): void {
  const motionDir = path.join(ROOT, "motion");
  const files = walk(motionDir, [".ts"]);

  const exported = new Map<string, string[]>();

  for (const file of files) {
    const content = fs.readFileSync(file, "utf8");

    const functionMatches = content.matchAll(
      /export (?:async )?function ([A-Za-z0-9_]+)/g

    for (const match of functionMatches) {
      const name = match[1];
      const current = exported.get(name) ?? [];
      current.push(file);

      exported.set(name, current);

        file: files[0],

      });
    }
  }
}

J. Validation

The validation code is already included above in scripts/validate.ts, but here is the exact validation strategy.

Automated checks

The validator checks:

1. YAML parses.
2. Zod schema passes.
3. FPS is allowed.
4. Dimensions are even.
5. Duration is positive.
6. Sequence steps do not exceed shot duration.
7. Sequence targets exist.
8. Transition targets exist.
9. Assets exist unless marked optional or system fonts.
10. HyperFrames scene entry exists.
11. Remotion composition is registered.
12. Duplicate primitive exports are detected.
13. Forbidden nondeterministic APIs are detected.

Manual visual checks

Automated validation does not prove quality.

The agent must also use:

bash
npm run inspect -- --project <project> --shot <shot>


Then review:

• projects/&lt;project&gt;/metadata/&lt;shot&gt;.inspection.md
• projects/&lt;project&gt;/metadata/&lt;shot&gt;.contact.png
• the preview MP4

Human approval

A shot is not complete until the human approves the visual result.

L. Agent Workflow

This is the exact workflow OpenCode should follow.

1. Intake

User provides one of:

• idea
• reference image
• reference video
• storyboard
• rough shot description

OpenCode does not immediately write scene code.

It first identifies:

• project
• shot ID
• runtime
• duration
• fps
• resolution
• purpose

2. Analysis

If a strong vision/reasoning model is available:

• it writes projects/&lt;project&gt;/references/analysis-&lt;shot&gt;.md
• it does not edit code
• it does not rewrite the repository

If unavailable:

• OpenCode creates the analysis itself conservatively
• it marks uncertainty in the analysis file

3. Specification

Create or update:

text
projects/<project>/specs/<shot>.yaml


The spec must validate.

4. Implementation selection

Use skills/hyperframes-vs-remotion.md.

If HyperFrames:

• create or modify: 
◦ hyperframes/scenes/&lt;sceneId&gt;/entry.ts
◦ hyperframes/scenes/&lt;sceneId&gt;/scene.ts

If Remotion:

• create or modify: 
◦ remotion/compositions/&lt;Composition&gt;.tsx
◦ remotion/Root.tsx
◦ remotion/registry.ts

5. Primitive check

Before writing animation code:

• search motion/core
• search motion/easing
• search motion/text
• search motion/transitions
• search motion/camera

Only create a new primitive if justified.

6. Determinism check

Before rendering:

• no Math.random()
• no Date.now()
• no timers
• seeded RNG only
• frame-based timing only

7. Validation

Run:

bash
npm run validate -- --project <project>


Fix all validation failures.

8. Preview

Run:

bash
npm run preview -- --project <project> --shot <shot>


9. Inspection

Run:

bash
npm run inspect -- --project <project> --shot <shot>


Review:

• preview file
• contact sheet
• inspection JSON
• inspection Markdown

10. Comparison

Compare output against:

• shot purpose
• sequence timing
• negative instructions
• motion hierarchy
• easing intent

11. Minimal correction

If there is a deviation:

1. identify the smallest broken area
2. change only that area
3. preserve unrelated work
4. revalidate
5. re-render
6. re-inspect

12. Iteration limit

For autonomous iteration:

• maximum 3 visual correction passes without human input
• if still failing, stop and report the likely issue

This prevents endless destructive rewriting.

13. Final render

When approved:

bash
npm run render -- --project <project> --shot <shot>


14. Resolve handoff

Move generated renders into Resolve manually or via project folder convention.

Do not attempt fragile timeline automation unless explicitly requested.

Explicitly Rejected Automation

The following are intentionally not automated by default:

Full Resolve timeline scripting

Reason:

• fragile
• version-dependent
• high maintenance cost
• low benefit for a single-operator system

Instead, use:

• consistent file naming
• shot folders
• manual import into Resolve
• optional CSV shot list

Automatic visual quality scoring

Reason:

• visual quality cannot be reliably unit-tested
• false confidence is dangerous

Instead, use:

• deterministic validation
• preview/contact sheet generation
• human review
• optional vision-model review as advisory only

Runtime network dependencies

Reason:

• nondeterministic
• fragile
• violates local-first constraint

Instead:

• local assets
• local fonts
• seeded procedural generation only
